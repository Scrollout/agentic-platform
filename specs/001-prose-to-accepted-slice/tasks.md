# Tasks: From a description to accepted working software, one slice at a time

**Input**: Design documents from `specs/001-prose-to-accepted-slice/` (revised after fresh review round 1)

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: Required. Contract-first and Outside-in put contracts and failing tests before code;
every check proves it can fail.

**Organization**: by user story; within a story: contract, generated code, failing tests, code,
fresh review.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 or US2

## Rules for every task

- **Test-first**: a test task and the implementation task that makes it pass are separate tasks,
  done by different authors. The implementer may not change the tests. An existing test, helper,
  fixture, recording, grader or eval case changes only after the project owner approves that
  specific change, recorded with a `Tests-approved-by:` trailer; agents refuse such a brief and
  report it (constitution, Existing tests change only with the owner's approval; ADR 0029).
- **Fresh review**: each story ends with a fresh-review task, done by a reviewer on another model than
  the work's author, following Review converges (at most 3 rounds). The reviewer works in its own
  copy of the repository (an isolated worktree holding the working tree's uncommitted and
  untracked changes), runs the test command there, and is made read-only by its tools (an agent
  type without file-editing tools, in that disposable copy), not by instruction. Parallel reviewers
  never share a copy.
- **Gate**: `/speckit-analyze` (fresh review) passed in round 2 on 2026-11-12, before T001; it is
  run again after any change to spec, plan or tasks. Re-run on 2026-11-12 after T012: round 1
  failed (3 HIGH: A1 oasdiff, A2 `cancelled` outcome, A3 npm pins), fixed in `f1d80c2`; round 2
  (Sonnet, fresh) passed: every finding resolved, no regressions. Re-run on 2026-11-13 after the US1
  follow-up tasks: 4 CRITICAL (C1 test-change rule, C2 gate not re-run, C3 reviewer setup, C4 hook
  not enforcing ADR 0029) and 5 HIGH, fixed in this tasks.md and data-model.md; to pass again before
  `/speckit-implement` continues with US2. Implementation runs through `/speckit-implement` from
  US2 on (US1 was implemented task by task without it). Round 1 of the 2026-11-13 re-run (Opus,
  fresh, at `3601b34`) failed (K1 to K4); fixed in `bab854b` and `d5de8e1`; round 2 (Opus, fresh,
  at `d5de8e1`) passed with 3 MEDIUM and 5 LOW, fixed or recorded in the next commit. Re-run on 2026-11-13 after T054a (Opus, fresh, at `0c9917d`): round 1 failed (C1 T054 before T046, D1 threat model, D2 pivot and compensation), fixed in `c9d96aa` with two owner-approved exceptions; round 2 (same reviewer, changed lines only) passed. Re-run on 2026-11-13 after T054e and T054c (Opus, fresh, at `38e1f13`): round 1 failed (F1, T054c before T053a's token wiring and T054b), fixed in `1f68bdb` with an owner-approved exception; round 2 passed. Re-run on 2026-11-13 after T049 (Opus, fresh, at `5fb28ab`): passed with 5 MEDIUM and 5 LOW, fixed or recorded in the next commit. The hook requires a `Tests-approved-by:` trailer when non-test Go code
  and test files are staged together, even when the tests are new; failing tests cannot be
  committed alone, so each unit's tests and code are committed together with the owner's trailer
  (playbook step 10, owner's choice 2026-11-13); Story 1's trailers naming "separate test author (Claude
  Sonnet), new test files only" record that no existing test changed, not an approval: only the
  owner approves (ADR 0029).
- **Done means**: tests pass, `python3 scripts/okf.py check` reports OK, `docs/log.md` records the
  change.
