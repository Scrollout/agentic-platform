# Tasks: From a description to accepted working software, one slice at a time

**Input**: Design documents from `specs/001-prose-to-accepted-slice/` (revised after fresh review round 1)

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: Required. Contract-first and Outside-in put contracts and failing tests before code;
every check proves it can fail.

**Organization**: by user story; within a story: contract, generated code, failing tests, code,
fresh review.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 or US2

## Rules for every task

- **Test-first**: a test task and the implementation task that makes it pass are separate tasks,
  done by different authors. The implementer may not change the tests. An existing test, helper,
  fixture, recording, grader or eval case changes only after the project owner approves that
  specific change, recorded with a `Tests-approved-by:` trailer; agents refuse such a brief and
  report it (constitution, Existing tests change only with the owner's approval; ADR 0029).
- **Fresh review**: each story ends with a fresh-review task, done by a reviewer on another model than
  the work's author, following Review converges (at most 3 rounds). The reviewer works in its own
  copy of the repository (an isolated worktree holding the working tree's uncommitted and
  untracked changes), runs the test command there, and is made read-only by its tools (an agent
  type without file-editing tools, in that disposable copy), not by instruction. Parallel reviewers
  never share a copy.
- **Gate**: `/speckit-analyze` (fresh review) passed in round 2 on 2026-11-12, before T001; it is
  run again after any change to spec, plan or tasks. Re-run on 2026-11-16 after the CI design (D41; round 1: 1 HIGH, fixed; round 2 clean) and after T107/T109's helper-script and version-home edits (no CRITICAL or HIGH; its 7 MEDIUM and 3 LOW fixed before the intent commit). Re-run on 2026-11-16 after the owner's decisions (`ubuntu-26.04` preview, the `config` job, T108 before the workflows, done when the task's run is green): no CRITICAL or HIGH; 4 MEDIUM fixed, 2 LOW noted. The hook requires a `Tests-approved-by:` trailer when non-test Go code

- **Done means**: the full check run passes once, when the task is finished, not on every commit (owner, 2026-11-16): a completed green `check.yml` run on GitHub covers the task's commit (its own push's run, or a later push's that contains it, since a newer push cancels an older run of the branch; research D41); until `check.yml` is green for the first time, one `scripts/check.sh` run on the host, by hand, recorded in the task; tests pass, `python3 scripts/okf.py check` reports OK, `docs/log.md` records the
  change.
