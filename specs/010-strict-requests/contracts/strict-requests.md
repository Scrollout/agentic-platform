Draft for the [plan](../plan.md). The authoritative copies live with their providers: the check

## Go interface (package `engine/checks`)

```go
// RequestShape is what the approved contract allows one request body to hold.
type RequestShape struct {
    Types           []string                 // JSON Schema type names; empty means any
    Properties      []Member                 // declared members, in contract order; nil when the schema has no properties
    RequiredMembers []string                 // in contract order
    Closed          bool                     // additionalProperties: false
    Items           *RequestShape            // array items; nil means any
}

// Member is one declared member of an object shape, by its exact name.
type Member struct {
    Name  string
    Shape *RequestShape
}

// RequestBody is one operation's request body.
type RequestBody struct {
    Key      string        // "POST /notes": the method in upper case and the contract's path
    Required bool          // requestBody.required
    Shape    *RequestShape
}

// RequestShapes finds every operation's request body in contract (the YAML text), in document
// order, following local $refs; a $ref target is one shared *RequestShape. An error means the
// text is not one YAML document without duplicate keys, or a body the fit conditions refuse.
func RequestShapes(contract []byte) ([]RequestBody, error)

// RenderRequestShapes is gen/request_shapes.go for bodies: the same bytes for the same bodies.
func RenderRequestShapes(bodies []RequestBody) []byte

// RequestShapesGenerated passes when the project's gen/request_shapes.go equals
// RenderRequestShapes of the approved contract; otherwise it fails naming the file. A contract or
// file it cannot read fails, naming what.
func RequestShapesGenerated(project string, approvedContract []byte) []CheckResult
```

## The delivered project (package `gen`)

- `gen/request_shapes.go` (generated by the procedure): `var requestBodies = map[string]*requestBody{...}`
  keyed by `"<METHOD> <path>"`, with one named variable per `$ref` target.
- `gen/requests.go` (from the template): `func refuseMalformed(key string, next http.HandlerFunc) http.HandlerFunc`;
  `next` itself when `key` has no body.
- `gen/std-http-handler.tmpl` (from the template): oapi-codegen v2.8.2's template, with each
  registration `m.HandleFunc(..., refuseMalformed({{.Method | toGoString}}+" "+{{.Path | toGoString}}, wrapper.<Handler>))`.
  Its first line names the release it was copied from.

## Behaviour

For an operation with a body, before the operation's parameters are read or its handler runs:

1. Read at most 1 048 576 bytes; more is refused.
2. An empty body: refused when `Required`, else the handler runs with it.
3. Not exactly one JSON value: refused.
4. Walk value and shape, depth first. At each object, in this order: a name twice (body order),
   a required member missing (`RequiredMembers` order), an undeclared member when `Closed` (body
   order), then each declared member present (`Properties` order); arrays item by item. A value
   whose JSON type is not in `Types` is refused (`integer`: a number with a zero fractional
   part). The first problem is the refusal.
5. Write the value again with only declared members, under their exact names, where `Properties`
   is not nil; numbers keep their text, except an `integer` written with a fraction or exponent,
   written again as an integer. Replace the body and its length; the handler runs.

## Messages

`<p>` is the member's RFC 6901 JSON Pointer from the body's root, written with `strconv.Quote`
and cut to 64 characters; `<t>` is the allowed types, each with its article (`a string`,
`an integer`, `a number`, `a boolean`, `an object`, `an array`, `null`), joined with ` or `.

| Problem | `message` |
|---------|-----------|
| larger than the limit | `the request body is larger than 1048576 bytes` |
| empty and required | `the request body is missing` |
| not one JSON value | `the request body is not valid JSON` |
| the root's type | `the request body must be <t>` |
| a name twice | `member <p> is named twice` |
| required and absent | `member <p> is required` |
| undeclared, object closed | `member <p> is not declared` |
| a member's type | `member <p> must be <t>` |

## Fit conditions

Reasons name each failing location as the other conditions do (`paths//notes/post`), sorted in
document order.

- `RefusalDeclared`: for every operation with `requestBody`, `responses."400".content."application/json".schema`,
  through local `$ref`s, has `type: object`, `required` equal to `[message]`, and
  `properties.message.type: string`. Reason: `<operation>: declares no 400 response with a JSON
  object body that requires only the string message`.
- `RequestBodiesSupported`: for every `requestBody`, `content` has exactly the key
  `application/json` (reason: `<operation>/requestBody: media types other than application/json: <names>`),
  and every schema reached from it, through local `$ref`s, has only allowed keywords (reason:
  `<location>: <keyword> is not supported in a request body`). Allowed: `type`, `properties`,
  `required`, `additionalProperties` (boolean), `items` (a schema), `$ref`; value keywords
  `maxLength`, `minLength`, `pattern`, `format`, `maximum`, `minimum`, `exclusiveMaximum`,
  `exclusiveMinimum`, `multipleOf`, `maxItems`, `minItems`, `uniqueItems`, `maxProperties`,
  `minProperties`, `enum`, `const`; annotations `title`, `description`, `default`, `examples`,
  `example`, `deprecated`, `readOnly`, `writeOnly`, `$comment`, and `x-` extensions. Any other key
  fails.
