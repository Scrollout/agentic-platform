## Go interface (package `engine/checks`)

```go
// RequestShape is what the approved contract allows one request body to hold.
type RequestShape struct {
    Types           []string                 // JSON Schema type names; empty means any
    Properties      []Member                 // declared members: properties in contract order, then names only in required, in required order (any type); nil when the schema has neither properties nor required nor additionalProperties: false; properties: {} is non-nil and empty
    RequiredMembers []string                 // in contract order
    Closed          bool                     // additionalProperties: false
    Items           *RequestShape            // array items; nil means any
}

// Member is one declared member of an object shape, by its exact name.
type Member struct {
    Name  string
    Shape *RequestShape
}

// RequestBody is one operation's request body.
type RequestBody struct {
    Key      string        // "POST /notes": the method in upper case and the contract's path
    Required bool          // requestBody.required
    Shape    *RequestShape
}

// RequestShapes finds every operation's request body in contract (the YAML text), in document
// order, following local $refs (a requestBody $ref to #/components/requestBodies included, every
// walk with a visited set); a $ref target is one shared *RequestShape. Properties, required and
// additionalProperties apply to an object value whether or not type is present; a name in
// required but not in properties is a declared member of any type. An error means the
// text is not one YAML document without duplicate keys, or a body the fit conditions refuse.
func RequestShapes(contract []byte) ([]RequestBody, error)

// RenderRequestShapes is gen/request_shapes.go for bodies: the same bytes for the same bodies.
func RenderRequestShapes(bodies []RequestBody) []byte

// RequestShapesGenerated passes when the project's gen/request_shapes.go equals
// RenderRequestShapes of the approved contract; otherwise it fails naming the file. A contract or
// file it cannot read fails, naming what.
func RequestShapesGenerated(project string, approvedContract []byte) []CheckResult
```

## The delivered project (package `gen`)

- `gen/request_shapes.go` (generated by the procedure, before `gen/declared.go`):
  `var requestBodies = map[string]*requestBody{...}` keyed by `"<METHOD> <path>"`; every shape an
  unexported `var requestShapeN = &requestShape{...}` (N from 1, document order of first use)
  without links, which `init()` then sets (members, items), so a recursive schema builds.
- `gen/requests.go` (from the template): `func refuseMalformed(key string, next http.HandlerFunc) http.HandlerFunc`;
  `next` itself when `key` has no body.
- `gen/std-http-handler.tmpl` (from the template): oapi-codegen v2.8.2's template, with each
  registration `m.HandleFunc(..., refuseMalformed({{.Method | toGoString}}+" "+{{.Path | toGoString}}, wrapper.<Handler>))`.
  Its first line is a Go-template comment `{{/* copied from oapi-codegen v2.8.2 pkg/codegen/templates/stdhttp/std-http-handler.tmpl; one change: refuseMalformed */}}`,
  so nothing of it reaches `gen/api.gen.go`.

## Behaviour

For an operation with a body, before the operation's parameters are read or its handler runs:

1. Read at most 1 048 576 bytes; more is refused (400, not 413, so it carries the declared body).
   The request's `Content-Type` is not judged.
2. An empty body, or one of JSON white space only: refused when `Required`, else the handler runs
   with it as sent.
3. `json.Valid` fails (not exactly one JSON value, or nested deeper than 10000 levels): refused.
4. The value is read with `json.Decoder.Token`; a name twice in one object, anywhere in the
   document, is refused: the one whose second occurrence comes first in the body (a pre-pass,
   before the walk of step 5).
5. Walk value and shape, depth first. At each object, in this order: a required member missing
   (`RequiredMembers` order), an undeclared member when `Closed` (body order), then each declared
   member present (`Properties` order); arrays item by item. A value whose JSON type is not in
   `Types` is refused. `integer` is decided on the number's text: a zero fractional part after
   the exponent is applied. A number written with a fraction or exponent whose plain form would
   exceed 32 digits is refused as not an integer; a plain integer literal is kept as sent, at any
   length. When `Types` holds `number` too, the value is kept as sent (no rewrite). `-0`, `-0.0`
   and `0e5` are written again as `0`.
   The first problem is the refusal (one message).
6. Write the value again with only declared members, under their exact names, where `Properties`
   is not nil; numbers keep their text, except an `integer` written with a fraction or exponent,
   written again as a plain integer. Replace the body and its length; the handler runs.

## Messages

`<p>` is the member's RFC 6901 JSON Pointer from the body's root, cut to its first 64 runes (no
ellipsis), then written with `strconv.Quote`; `<t>` is the allowed types, each with its article (`a string`,
`an integer`, `a number`, `a boolean`, `an object`, `an array`, `null`), joined with ` or `.

| Problem | `message` |
|---------|-----------|
| larger than the limit | `the request body is larger than 1048576 bytes` |
| empty and required | `the request body is missing` |
| not one JSON value | `the request body is not valid JSON` |
| the root's type | `the request body must be <t>` |
| a name twice | `member <p> is named twice` |
| required and absent | `member <p> is required` |
| undeclared, object closed | `member <p> is not declared` |
| a member's type | `member <p> must be <t>` |

## Fit conditions

Reasons name each failing location as the other conditions do (`paths//notes/post`), sorted in
document order.

- `RefusalDeclared`: for every operation with `requestBody`, `responses."400".content."application/json".schema`,
  through local `$ref`s, has `type: object`, `required` equal to `[message]`, and
  `properties.message.type: string` with no value keyword on `message` (`maxLength`, `minLength`,
  `pattern`, `format`, `enum`, `const`), and the object schema itself uses only `type`,
  `required`, `properties`, `additionalProperties` and annotations. The key `400` counts written
  as `400` or `"400"` (both present: not fit); `4XX` and `default` do not count; a response that
  is a `$ref` to `#/components/responses/...` is followed. Reason: `<operation>: declares no 400 response with a JSON
  object body that requires only the string message`.
- `RequestBodiesSupported`: for every `requestBody`, `content` has exactly the key
  `application/json` (reason: `<operation>/requestBody: media types other than application/json: <names>`),
  and every schema reached from it, through local `$ref`s (with a visited set), has only allowed
  keywords (reason: `<location>: <keyword> is not supported in a request body`); a body with no
  `schema` (`<operation>/requestBody: no schema`) and a `type` naming anything but `null`,
  `boolean`, `object`, `array`, `number`, `string`, `integer` fail too, as do a type list other
  than one type and `"null"` (the pinned oapi-codegen generates no other), an empty type list,
  a type list item that is not a string (an unquoted YAML `null`: write `"null"`), a boolean
  schema (`items: true`, `schema: false`), and a YAML anchor or alias in a schema. A name of a
  property, or a key under an `x-` extension, is never judged as a keyword. Allowed: `type`, `properties`,
  `required`, `additionalProperties` (boolean), `items` (a schema), `$ref`; value keywords
  `maxLength`, `minLength`, `pattern`, `format`, `maximum`, `minimum`, `exclusiveMaximum`,
  `exclusiveMinimum`, `multipleOf`, `maxItems`, `minItems`, `uniqueItems`, `maxProperties`,
  `minProperties`, `enum`, `const`; annotations `title`, `description`, `default`, `examples`,
  `example`, `deprecated`, `readOnly`, `writeOnly`, `$comment`, and `x-` extensions. Any other key
  fails, `nullable` among them (a type list allows `null`).
