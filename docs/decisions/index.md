* [ADR 0002: Build the platform on Docker Agent](0002-build-on-docker-agent.md) - Docker Agent is the agent definition format and runtime the platform is designed around; the platform adds what multi-tenant use needs.
* [ADR 0003: AHP is the client-facing session protocol](0003-ahp-client-session-protocol.md) - Clients (web console, IDE, CLI, mobile) share and steer live agent sessions through the Agent Host Protocol; the platform's host bridges AHP to Docker Agent.
* [ADR 0004: Contract-first toolchain, service-owned APIs and versioning](0004-contract-first-toolchain.md) - Each microservice owns its OpenAPI 3.1 contract and operations list; APIs use ARM-style date-based stable and preview api-versions per service; open-source generators and a CI tool set enforce contract, compatibility, conformance and drift.

* [ADR 0026: Deterministic workflow engine with agents as state workers](0026-deterministic-workflow-engine.md) - Candidate approach in which a declared, durable state machine runs each piece of work, agents act only inside its states, and deterministic guards decide every transition; includes the spike that tests it.
* [ADR 0027: Contract-driven frontend](0027-contract-driven-frontend.md) - The console is a shell with one UI module per service, modelled on the Azure portal, built against the API contracts and AHP in parallel with the backend; every known weakness of the stack is removed or mitigated.
* [ADR 0028: Sign the platform's images locally with cosign](0028-sign-platform-images-locally.md) - Images the platform builds are pushed to a local registry with an SBOM and provenance, signed with cosign and a key pair kept outside the repository, and verified offline by the launcher before anything starts.
* [ADR 0029: Existing tests change only with the owner's approval](0029-existing-tests-change-only-with-owner-approval.md) - An existing test, fixture, grader, threshold or eval case changes only after the project owner approves that change in the commit that makes it; agents refuse briefs that would change one and report them; a fresh agent's judgement no longer suffices.
* [ADR 0030: Agent steps run on Docker Agent's API server; checks and procedures run in a check service with its own contract](0030-agent-steps-on-docker-agent-checks-in-a-check-service.md) - Each agent step container runs the pinned Docker Agent serve api and the engine calls it with one session per attempt; checks run in a read-only check service and each fixed procedure in its own step worker, both serving one versioned contract reached only by the engine; reuse keys use the model each agent definition pins.
* [ADR 0031: A review finding blocks only when its rule's tests, rerun against the current code, fail at the file it names](0031-review-findings-confirmed-by-rerunning-rule-tests.md) - Superseded in part by ADR 0039 (how a finding is confirmed). The check service confirms a blocking review finding by rerunning the tests of the rule it names and requiring a failure at the named file; this replaces passing the attempt's other check verdicts as confirmations.
* [ADR 0032: The new project's version history is a git repository kept by a project worker](0032-project-version-history-kept-by-a-project-worker.md) - A project worker, a third deployment of the check program with the projects folder writable, commits each accepted step, restores the project to its last commit before every attempt, and writes a replay's reused step files; the engine keeps no git and no project mount.
* [ADR 0033: The project worker runs in its own small image](0033-project-worker-in-its-own-small-image.md) - The project worker runs the static check binary in its own image, ap-project, on the Alpine pin with git pinned by exact package version; the check image keeps its Alpine base without git.
* [ADR 0034: Step worker grants are files the engine reads at each authentication](0034-step-worker-grants-as-files-read-at-each-authentication.md) - The launcher writes one grant file per step worker, named by the SHA-256 of its token, into a folder only the engine mounts read-only; the engine reads it at each worker-token authentication, so removing a file revokes the grant and a malformed one grants nothing.
* [ADR 0035: Spec Kit during implementation](0035-spec-kit-during-implementation.md) - During implementation a discovery is fixed at its source, a change of intent updates spec, plan and tasks in that order as its own reviewed change before code, analyze is re-run until clean after every artifact change, implement runs in validated stages behind the checklist gate, and converge runs after each user story and before a feature is done.
* [ADR 0036: Step containers are kept per project; resume reuses them and replay builds a new project](0036-step-containers-per-project-resume-reuses-them.md) - Each project of a slice gets its own step containers, named by slice, step and the project's hash and labelled with the project, kept until ap down; build-workers refuses while a run of the slice is active, resume registers the run's own containers again or, when they are gone, points to build-workers --resume, which rebuilds them for that interrupted run only; replay always builds a new, empty project.
* [ADR 0037: The terminal client's run commands detach on Ctrl-C and exit by run state; ap test runs on the host](0037-terminal-run-commands-exit-codes-and-test-on-host.md) - build, resume, replay and run exit with one code per run state (done 0; waiting, interrupted and handed-over 2; expired 5; cancelled 6), compare exits 7 when the runs differ, Ctrl-C (130) or SIGTERM (143) stops following while the run continues, and ap test builds a suite in the pinned Go container and runs its test binary on the host with the developer's own Docker access, an owner-approved exception to the test-security rule.
* [ADR 0038: The test lab runs the build path as the platform does, with step agents answering from synthesised recordings](0038-lab-runs-the-build-path-with-synthesised-step-recordings.md) - The acceptance lab starts the check service, the project worker and per-project step workers from settings proved equal to compose.yaml, with grants, registrations and a durable store, and the step agents answer from recordings synthesised from reviewed answer scripts, never recorded live, replayed by WireMock with exact matching.
* [ADR 0039: A blocking review finding is confirmed by a new failing witness test the review writes](0039-review-findings-confirmed-by-a-new-witness-test.md) - A blocking review finding carries a new Go witness test for its rule in the review's own folder `review/r<n>/`; the check service runs only that test with coverage and confirms the finding when it fails having run the named line, per the coverage profile; the fix step must make it pass without changing it, and witnesses stay in the delivered project, unchangeable by every later step. Supersedes the confirmation part of ADR 0031.
* [ADR 0040: An open review round's result is kept and reused like an accepted step's](0040-open-review-round-result-kept-and-reused.md) - A review round left with blocking findings open keeps its result (findings, witnesses, project files, its NoBlockingFindingOpen result) under its reuse key, which covers the round, marked open; a later run of the same input reuses it as a ResultReused with open_round, so the fix and the later rounds are reused too and a replay with more than one review round is identical. Reuse runs no check; resume after an open round goes straight to the fix.
* [ADR 0041: A test check needs a go test event for every declared test, and each check call runs in a fresh folder](0041-test-checks-need-an-event-per-declared-test-in-a-fresh-folder-per-call.md) - AllTestsPass and TestsFailAgainstStub read `go test -json -count=1` events and need one for every top-level Test function declared under `tests/**` and `review/**` (AllTestsPass a pass for each; TestsFailAgainstStub an event for each and at least one fail), so a test that vanishes fails the check; each check call runs with its own new, empty temporary folder as `GOCACHE`, `GOTMPDIR`, `TMPDIR`, `HOME` and `GOPATH`, removed after the call, and the pinned modules' cache shared read-only.
* [ADR 0042: Only a finding the check confirmed is recorded as blocking](0042-only-a-confirmed-finding-is-recorded-as-blocking.md) - NoBlockingFindingOpen's verdict names the findings its witness runs confirmed (`confirmed`, positions in the request's findings); the engine records exactly those as blocking and every other finding, the agent's unconfirmed claims included, as a suggestion, and only confirmed findings reach the fix, the next round's reuse key, the hand-over and the run's open findings. Amends what ADR 0039 means by blocking in the run record.
* [ADR 0043: Module boundaries are checked by go-arch-lint, one archfile per Go module](0043-module-boundaries-checked-by-go-arch-lint.md) - Each Go module in src/go.work declares its packages as components and their allowed imports in a .go-arch-lint.yml; go-arch-lint v1.19.1, built from source in the pinned Go image and run offline from scripts/check.sh and the pre-commit hook, fails any undeclared import and any unmapped package. The platform's own modules come first; generated projects come later.
* [ADR 0044: The full checks run on GitHub-hosted runners, in a public repository](0044-full-checks-run-on-github-hosted-runners.md) - Superseded in part by ADR 0048 (when the evals run). The repository moves to github.com/Scrollout/agentic-platform, public; GitHub Actions runs the full scripts/check.sh and the acceptance suites on standard hosted runners on every push, the live evals with the test key from the environment dev when an agent, prompt, model or Docker Agent changes, and the pre-commit hook keeps only the quick static checks. No pull requests, branch protection or code owners.
* [ADR 0045: GitHub's free scanners are on for the public repository](0045-github-free-scanners.md) - Secret scanning with push protection, Dependabot alerts, CodeQL default setup for Go, Python and the workflows, and private vulnerability reporting are enabled; Dependabot's pull requests are not, since the project uses none.
* [ADR 0046: CI test results are JUnit reports shown by action-junit-report](0046-ci-test-results-are-junit-reports.md) - Go tests run through gotestsum and the Python check tests through testrun.py, both writing JUnit XML; action-junit-report shows each test job's results in its summary with a read-only token.
* [ADR 0047: End to end on the Compose stack with the recorded model](0047-end-to-end-on-the-compose-stack-with-the-recorded-model.md) - scripts/e2e.sh drives the real ap/Compose stack under gVisor against the recorded model, through a test-only Compose override file the launcher accepts only from src/tests/e2e/.
* [ADR 0048: The live evals are started by hand and gated before main](0048-evals-started-by-hand-and-gated-before-main.md) - Supersedes ADR 0044 on when the live evals run. evals.yml has no push trigger; the owner starts it, and it runs only the suites whose inputs changed since the last green evals run. A keyless check job lists pending suites, passing with a notice on the feature branch and failing on main; the owner merges only when none is pending.
* [ADR 0049: A fresh review judges the CI run of the pushed commit](0049-fresh-review-judges-the-ci-run.md) - Amends the constitution's Fresh review rule (2.2.0). The fresh reviewer runs the tests that judge the change in its own copy; the full test command's run is the CI run of the pushed commit, and the change is not done until it is green.
* [ADR 0050: A failed eval job keeps its outputs for 7 days](0050-failed-eval-jobs-keep-their-outputs.md) - When a live eval job fails, evals.yml uploads its report folder (each trial's answer and events, report.json) as a workflow artifact kept 7 days, with actions/upload-artifact pinned by commit; a passing job uploads nothing.
* [ADR 0051: A green test report adds nothing to the job's summary](0051-a-green-test-report-stays-quiet.md) - The CI test jobs' action-junit-report steps set skip_success_summary, so a job whose tests all pass writes no results table; a failing job still shows the counts and each failed test; require_tests fails a step that finds no result. Replaces ADR 0046's counts for green jobs.
* [ADR 0052: A green test job writes no summary at all](0052-a-green-test-job-writes-no-summary.md) - The CI test jobs' action-junit-report steps set job_summary only when the job has failed, so a green job has no summary, not one that holds only a separator; failures still show the counts and each failed test. Replaces ADR 0051's separator-only summary for green jobs.
* [ADR 0053: Each check job runs only when a file it judges changed](0053-check-jobs-run-for-the-files-they-judge.md) - .github/check-jobs.yaml declares per check.yml job the paths it judges or that it always runs; the config job selects the jobs from the files changed since the branch's last green check run. Supersedes ADR 0044's every step on every push.
