# src/engine

The engine: the state machine, checks, fixed procedures, run store and the engine API (contract under api/preview/).

Generated server interfaces and types: `api/gen/`, made by `scripts/generate.sh` from `api/engine.oapi-codegen.yaml`; never edited or committed.

Rate limits, both from the contract's `x-limits` and both a one-second sliding window: a request with an accepted token counts only against that token (`requests-per-second-per-token`); a request with no token, or one the engine does not accept, counts against its source address (`requests-per-second-per-address-without-token`), the host part of the connection's peer address, never a forwarding header. Such requests get 401 up to that limit and 429 with `Retry-After` beyond it. The limiter drops windows idle for a second or more, so its memory follows the addresses active in the last second, not every address ever seen.

The limits live once, in the contract's root `x-limits`; the engine refuses to start without a positive integer for each of its four keys, and the Spectral rule `ap-limits-declared` in `api/ruleset.yaml` (function `api/ruleset-functions/declaresLimits.js`) fails any service contract that lacks one.

Run store (`store/`): `store.Open(dir, ids)` takes the contract's schemas (`*slice.Schemas`) and parses every slice ID, run ID and artifact hash it is given, and every one it reads back from disk, with them; the patterns are not repeated in Go. The engine command opens it in `ENGINE_STORE_DIR` with the schemas of the contract version it serves (`api.ContractFiles()` through `slice.LoadSchemasFS`); the API reads `artifact_count` from it and erases a deleted slice's data in it. It also keeps the slices (T038b), behind `slices.Records`: `slices/<id>/slice.json` holds each slice's record and `slice-sequence.json`, at the store's root, the last slice ID given out, both readable JSON replaced atomically (temporary file, fsync, rename, fsync of the folder) and written before the change is reported; `Open` removes leftover temporary files and `EraseSlice` removes the record with the slice's folder. The slices package owns the record's format: the slice, its contract baseline (the last approved contract), its latest compatibility and lint results and the example IDs earlier revisions dropped with their scenario digests (`dropped_examples`, compared from the last examples that parsed, `examples_base`, so a drop across an invalid revision counts; a record written before it was kept has none, so the IDs its examples carry now are the only ones known used), so a restart serves the same parts, hashes, checks, questions, answers, approvals, history and state without calling the lint service or the analyst. On load each record is checked: its layout version, the slice ID against the contract's rule, the state, each approval's part and hash against the contract's rule, and that the stored part hashes are those of the stored parts. The ID sequence keeps the IDs of deleted and reserved slices from being given out again; if storing it fails, `Reserve` makes no reservation (T038j): `CreateAs` with the ID it returned fails with `OperationFailed` and stores nothing, `Create` fails with `OperationFailed` too, and the service never gives that ID out again; the next ID after a successful write was never stored. `createSlice` then answers 202 and its operation fails `OperationFailed`, without the storage error's text.

Slices (`slices/`): `slices.New(Config)` takes the contract's schemas, the analyst and an oasdiff comparison (`ContractDiff`), and the catalogue pattern's `pattern.yaml` bytes for `checks.Fit` (without them every contract carries a failed `PatternFit` and cannot be approved). `Create` builds a slice from the analyst's proposal, offers an approved slice of the same description instead, and asks to narrow an empty or multi-use-case description. Every change runs the schema, `slice.Trace`, `ExampleTagged` (`slice.ExampleTags`: each scenario carries the `@R-<n>` of its `Rule:` block and an `@E-<n>` no other scenario carries, and no `@E-<n>` an earlier revision or edit dropped on another scenario: the service keeps each dropped ID per slice with a digest of its scenario (`slice.ExampleScenarios`), and an ID that comes back on a different scenario fails `ExampleTagged` on the rules part, naming it, while restoring the dropped scenario itself is no reuse; T037d) and pattern checks again, and a changed contract is compared with the last approved one, or with an empty document before any approval; a failing check is stored in the slice's `checks`, never returned as an error, each marked `Check.Pattern` (check_result `pattern`, kept on disk as `from_pattern`) when it is a pattern condition (T039c), and `Approve` refuses the failing part, and a part an open question concerns (`ContradictionOpen`). More questions than `slice.schema.json` allows (`questions` maxItems, 10 today, read through `Schemas.MaxQuestions`) gives `TooManyQuestions`; `slices.New` refuses schemas that set no such limit or no free-answer length (T071). A proposal is unusable when it breaks `slice-proposal.schema.json`, `slice.Trace` cannot parse its Gherkin examples or its OpenAPI contract (its `Finding.Syntax` findings), or `checks.Fit` cannot read a contract that YAML parses (duplicate keys, several documents: Fit marks those results `Unreadable`; an unreadable pattern stays a stored failed `PatternFit`, T037c); `Create` then asks the analyst again with that proposal and its faults (`AnalystInput.Previous`, `AnalystInput.Errors`), up to the pattern's `limits.attempts` (one attempt without a pattern or a positive limit), and after the last attempt fails with `OperationFailed` naming the faults and stores nothing; the `proposed` (and on `Answer` the `revised`) history entry records the number of calls in `attempts`. An analyst error, `NarrowDescription` and `TooManyQuestions` are returned, not retried, and every other failing check is stored as before. Each part's hash is the SHA-256 of its RFC 8785 canonical JSON, written by package `canonical/` (the one owner of these hashes, which the step check `ContractHash` reuses) for the strings, arrays and objects a part holds (no part holds a number); an approval holds only while that hash is unchanged, and a change to the part withdraws it. After any change (`Replace*` or `Answer`), every other part that now fails a check, such as rules naming a removed goal or a contract whose `x-rules` names a removed rule, loses its approval too, recorded as a `withdrawn` history entry whose `refs` are those parts; a slice is never `approved`, offered for reuse or buildable while a check fails. With `Config.Lint` (`ContractLint`: Spectral with OpenAPI's standard rules, not `api/ruleset.yaml`), a new or changed contract is linted too: each error-level finding fails `ContractLint`, warnings do not, and a lint that cannot run fails it; without a lint every contract carries a failed `ContractLint` and cannot be approved. Schema failure reasons name the part and the JSON pointer of the fault in the parts document and say what is wrong in words, never a schema's URL or a local path. A `ContractCompatibility` or `ContractLint` reason keeps locations out (T037e, `slices/checks.go`): a finding's text (`scrubFinding`) loses anything with a URL scheme (`x://`, `file:`), a `host:port` (single-label and IPv6 too), Windows drive and UNC paths, `~/` paths and absolute paths ending in a file name with an extension, while API paths such as `GET /run/{id}` stay; the finding's ID and the lint rule's code stay. A runner's error never goes into a reason: the check says only that the comparison or the lint could not run, and the full error goes to `Config.Log` (`*slog.Logger`, nil discards; the engine command gives it a JSON handler on stderr, and no token is logged). `Answer` records answers to open questions (an option or a text no longer than `slice-defs.schema.json` allows, `answer` text maxLength, 200 today, read through `Schemas.MaxAnswerText`; an answered or unknown question gives `QuestionNotOpen`), sends the description, the current proposal and all questions with their answers to the analyst under the same unusable-proposal retry, takes the revised parts and the revision's new questions (next `Q-<n>` IDs, at most 10 questions in total, else `TooManyQuestions`), checks again, withdraws the approval of each part whose hash changed and appends `answered` then `revised`; an answered question no longer blocks approval, and a refused answer changes nothing. The analyst runs without the service's lock; if the slice changed meanwhile the revision is dropped. oasdiff and the lint run without it too (T040b): `replace` reads the slice under the lock, runs both unlocked, then takes the lock again and applies the change to the slice as it is then, storing it before it is reported, so a slow comparison or lint holds up no other slice. Changes of one slice wait for each other on a per-slice lock, so two concurrent changes both land; when an approval changed the baseline meanwhile, both run again, at most 3 times, then the change ends `OperationFailed`. `Delete` erases a slice; its ID is not given out again. `List` returns the slices newest first. `Reserve` gives out the next ID from the sequence `Create` also draws from, and `CreateAs` creates a slice under a reserved ID (a malformed, unreserved or used ID gives `InvalidRequest`, and one given out while the ID sequence could not be stored `OperationFailed`, before the analyst runs); an ID given out is never given out again, also not after a failed `CreateAs` or a `Delete`. `CheckAnswers` and `CheckApprove` refuse exactly as `Answer` (before its analyst call) and `Approve` do, and change nothing. `Buildable` gives `PatternDoesNotFit` while a pattern condition fails, then `NotApproved` while a part holds no approval at its current hash or any check fails. `Slice.ArtifactCount` (`artifact_count`) is not kept by the service; it is filled from the run store's `ArtifactCount(sliceID)`, the number of distinct artifacts stored for the slice's runs. With `Config.Records` (the run store in the engine), slices are durable: `New` loads every stored slice and the ID sequence and fails, naming the slice, on a record it cannot read or check (fail closed); every change is written before it is reported; a history entry's `attempts` is stored when set, and a record written before it was kept loads without it. Without it slices live in memory only.

Step checks (`checks/steps.go`, T048): plain functions over the project's folder and the pattern's values, each returning `CheckResult`s whose failing reason names the file, import, rule or hash at fault, and failing when it cannot run. `Scope` (ScopeKept) and `TestsUnchanged` compare two trees (`dir/**` is everything below dir, other entries exact paths); `Dependencies` (DependenciesAllowed) matches every import of the project's `.go` files (`vendor/` aside) and each `go.mod` require outside its own module (read with `golang.org/x/mod/modfile`; any `replace` directive and any symlink in the project fail it, and `vendor/` is not scanned since only the generate procedure writes it) against the Go package patterns (`std`, a path, `path/...`): imports and direct requires must match an allowed entry, and no import or require, `// indirect` ones included, may match a forbidden one (forbidden wins); `DependenciesOf` (T049b) runs the same check on only the step's own writable files (and `go.mod` when the step may write it), which is what the check service judges; `NotOwn(tree, writable)` drops the step's own writable paths (`dir/**` everything below dir, other entries exact paths) before TestsUnchanged and GeneratedCodeUnchanged compare trees (the seam `internal/app/app.go`), in the check service and in the step-agent evals alike (T049c); `TestsFailAgainstStub` (`go test -json -count=1 ./tests/...`: the tests build, every declared test under `tests/` has a result event, `pass`, `fail` or `skip`, so none vanished, and at least one fails), `AllTestsPass` (`go test -json -count=1 ./...` exits 0 and every declared test has a `pass` event; one with no event, `fail` or `skip` fails it, named with its package's import path, and a project with no declared test fails it; research D37, ADR 0041, T093), `GodogStrict` (EveryExampleBound: `go test -json -count=1 ./tests/...`, whose godog TestSuite runs the examples with `Strict`; godog's summary and the `=== RUN` lines are read from the events' `Output`, rejoined into text; a run with no scenario count falls back on the events: `tests/` declares a test and each has a result event; judges binding, not the exit code: fails on a build or setup failure, an undefined, pending or ambiguous step, or fewer scenarios than `features/slice.feature` holds, colour codes stripped first; T049b; the scenarios run are counted only from godog's own summary, a `<n> scenarios (...)` line directly followed by its steps line, the last one per top-level test, so a line a test prints cannot add to it, and the file's scenarios are its Gherkin pickles, so each Scenario Outline Examples row counts and `Scenario:` in a docstring or comment does not; a file that is not Gherkin fails; T049c) and `GenerationDrift` (GenerationRepeatable, run on a temporary copy) run the go toolchain through a `GoRunner`, whose real form `NewGoRunner` (each command bounded by 10 minutes, the pattern's step budget; `NewGoRunnerWithTimeout(d)` for another bound, a timed-out command killed with its process group and failing the check) runs the project as its own module with no network (`GOWORK=off`, `GOTOOLCHAIN=local`, `GOPROXY=off`: modules come from `vendor/` or the module cache; `scripts/check.sh` downloads the pinned godog into the shared cache first, so `TestGodogStrictReal` runs offline); `ContractHash` (ContractMatchesApproval) compares `canonical.ContractHash` of `api/openapi.yaml`'s text with the approval's hash. The test checks read `go test -json` events (cmd/test2json), never summary lines, so a test whose code ends the test binary before it runs (an `init` calling `os.Exit(0)`) leaves no event and fails the check that needs it (code in the test binary can still print lines test2json turns into events; a known limit, research D37). The declared tests (`declaredTests` in `checks/witness.go`, beside `readEvents`) are the top-level test functions of the `_test.go` files under `tests/**` and `review/**`, read with `go/parser` by the go command's rule (`Test` then nothing or a character that is not lower case; one `*T` parameter, no result; so not `TestMain(*testing.M)`, benchmarks, examples, fuzz targets or subtests), each matched by its package's import path (go.mod's module path and the file's folder); the code step's own tests run but declare nothing. Every `go test` a check runs carries `-count=1`. The review checks are in `checks/missing.go` (below).

Missing step checks (`checks/missing.go`, T054e), as the check contract's runCheck states them: `ExamplesMatchApproval(project, approved)` (`features/slice.feature` byte for byte the approved `examples` text); `GeneratedCodeBuilds` (`go build -mod=vendor ./...`, offline, so a module only in the module cache does not count); `TestsBuild` (`go test -c -count=1` of every package into a folder outside the project; no test package fails); and `GeneratedCodeUnchanged` (as `TestsUnchanged`, for the generate step's writable globs). The review checks (`checks/witness.go`, T075, research D35, ADR 0039): `FindingsCarryEvidence(r, project, Review{Before, Own, Fixable}, findings)` and `NoBlockingFindingOpen(...)` run only the witness test a blocking finding names (`Finding.Witness{File, Test}`), as `go test -json -count=1 -covermode=set -coverpkg=./... -coverprofile=<temp folder> -run '^<test>$' ./review/r<n>/`, offline, and, when it fails having covered the finding's line (the profile's block of the file's import path in the module), the baseline with `-run '^$'`; the finding is confirmed only when the baseline does not cover the line. A witness run with no result event for its test (it never ran) cannot be judged and fails the check; the baseline runs no test by design and needs only its package's end event and profile (D37). It is run only when the finding's file is a regular file `Fixable` (the code step's writable) matches, and the witness is a `_test.go` file directly in `review/r<n>/` of its rule `R-<n>`, matched by `Own`, not in `Before`, declaring the top-level `TestR<n>...` (no digit after `<n>`) it names; anything else is a suggestion. NoBlockingFindingOpen fails per confirmed finding, naming its rule and file, and its verdict's `confirmed` holds the confirmed findings' positions, ascending, on every verdict (`[]` when it passes; `CheckResult.Confirmed`, T096, ADR 0042); FindingsCarryEvidence fails for a blocking finding without a rule, a project file or a line, and both fail for a witness run that cannot be judged (a witness that does not build). `WitnessesUnchangedOf(b, a, globs, mayAdd)` is TestsUnchanged's witness rule: no witness in `b` is changed or removed, and one is added only when `mayAdd` (the judged step holds `witnesses`). The check service gives them the request's `before`, the step's writable, the earlier `code` step's writable and each finding's `witness`; TestsUnchanged adds the witness rule for the step whose outputs hold `witnesses`, earlier or the judged one; and a step may declare `findings` (not a set of files) beside one file-set output. `ScopeOf`, `TestsUnchangedOf` and `GeneratedCodeUnchangedOf` compare `Tree`s (path to SHA-256), so a folder can be compared with a `before` hash list; go test durations are dropped from reasons so the same request gives the same answer.

Shared by checks, procedures and the check service (`checks/shared.go`), each rule once: `MatchGlob` (the catalogue's glob dialect), `HidePaths` (a reason names project paths only) and `CommandEnv` (the environment of every command run on a project: only PATH, HOME, TMPDIR, XDG_CACHE_HOME and the Go variables GOROOT, GOPATH, GOCACHE, GOMODCACHE, GOFLAGS, CGO_ENABLED from the process, then the caller's extra entries, a later one winning, then `OfflineGo`; never a token or an ENGINE_*, CHECK_* or AP_* setting). `NewCallFolder(extra, cacheBase)` (T094, research D37, ADR 0041) is one call's own new folder below `os.TempDir()`, its `GOCACHE` starting as a copy of `cacheBase` when given (`os.CopyFS`: fresh modification times and owner-writable copies, so go's trimming keeps them and the base stays untouched; a `cacheBase` that is not a folder is an error and leaves no folder): its `Env` gives `GOCACHE`, `GOTMPDIR`, `TMPDIR`, `HOME` and `GOPATH` inside it and `GOMODCACHE` the shared module cache (`ModuleCache(extra)`: the last `GOMODCACHE` of `extra`, else the first entry of its `GOPATH` with `/pkg/mod`, else the same from the process, else `$HOME/go/pkg/mod`, resolved before the call sets its own `GOPATH`), given last so they win over the host's; `Scratch` makes a scratch folder inside it, and `Remove` removes it with everything in it, read-only entries too. A `GoRunner` that is a `Scratcher` (the check service's) gets the checks' scratch folders (GenerationDrift's copy, TestsBuild's binaries, the witness runs' profiles) made in its call's folder; `NewGoRunner`'s runner, used outside the check program (the package tests and the step evals), keeps the host's environment and `os.TempDir()`.

Check service (`checksvc/`, T054e): `checksvc.NewHandler(Config{Token, Project, Procedure, Step, OapiCodegen, Template, Env})` serves the check contract (`src/check/api`, research D29) on its generated strict server. With `History` set it is the project worker (commitStep and restoreStep; the other three 404); with `Procedure` set, the procedure step's worker for that procedure and `Step` (runProcedure only; the others 404); with neither, the check service (runCheck, readStepFiles; runProcedure is 404 UnknownProcedure). The check service and the procedure workers answer commitStep and restoreStep with 404 VersionHistoryNotServed. `.git` at the project root is left out of every folder walk, and a path or writable entry with a part `.git` in any letter case is not a ProjectPath. The version, the `x-limits` and the request body schemas are read from the embedded contract (`gen/`, copied by `scripts/generate.sh`; `src/engine/checksvc/gen/` is gitignored), so they have one home. Every request passes, in order: the token (401; without an accepted token counted per peer address, 429 beyond), the token's rate limit (429), the api-version (400), the calls running (503 Busy beyond `calls-at-once`), the body size, Content-Type and schema (400 InvalidRequest), then the operation within `time_limit_seconds` (504; every go command runs in its own process group, killed whole). `checkByName` (`checksvc/checks.go`) is the one map from pattern check names to `engine/checks`, and `procedureByName` from procedure names to `engine/procedures`. Every folder walk uses lstat and every file is opened with `O_NOFOLLOW`: an entry that is a link, not a regular file or folder, or not a ProjectPath fails runCheck naming it and is 422 UnreadableProject for readStepFiles and runProcedure. runCheck recomputes the framed hash of every output first, and binds every earlier step's output given as an input through `before` (each of its files in the folder equals its entry there, none missing or added, except a path the judged step may write); such an input's framed hash is also recomputed when no step after its producer in `earlier_steps` nor the judged step may write any of its paths (T082). runProcedure writes exactly the files of the step's writable set and removes the stale ones; `completed: false` writes nothing. Reasons name project paths only. A file larger than `x-limits.project-file-max-bytes` is never read whole, and a response larger than `response-body-max-bytes` is not sent (500 ResponseTooLarge). Each runCheck and runProcedure call gets its own `checks.CallFolder`, made before its first command and removed when the call ends, whether it passes, fails, times out (after its processes are killed) or is cancelled; the service's commands, `go` (the witness runs included) and oapi-codegen alike, get `CommandEnv` of `Config.Env` and then the call folder's variables, with no CHECK_* variable and no entry holding the token, so nothing a check writes through `GOCACHE`, `GOTMPDIR`, `TMPDIR`, `HOME` or `GOPATH` survives the call. `Config.GoCacheBase` (`CHECK_GOCACHE_BASE`; the image's `/opt/gocache-base`, research D37 "Cost") is the read-only warm base cache each call copies as its `GOCACHE`; empty, each call starts from an empty cache (the package tests, a developer's host); set but not a folder, the call fails with 500 before any command runs. One AllTestsPass call on the lab's example project (T094): 0.4 to 0.6 s with the old shared cache, about 13 to 17 s with an empty one, 3.0 to 3.1 s with the base, of which the copy of the 117 MB, 2,333-file base takes about 0.45 s. The base holds the standard library only: the vendored modules' cache keys hold the project's folder (no `-trimpath`), which differs per project, so they compile in each call. Project worker (`checksvc/history.go`, T053c, research D30): commitStep and restoreStep in the contract's order, one project at a time. Git (`Config.Git`, default `git` on PATH) runs with a fixed environment (`GIT_DIR`, `GIT_NO_REPLACE_OBJECTS=1`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`) and fixed `-c` options (no fsmonitor, hooks, automatic gc or signing), through plumbing only (`init --template=`, `hash-object -w --no-filters --stdin-paths`, a fresh `update-index -z --index-info` with every file 100644, `write-tree`, `commit-tree`, `update-ref` with the old value, `cat-file --batch`); paths reach it on standard input only, and each blob ID is checked against the bytes the worker read. The record (`<History>/<project>.json`: commit, parent, trailers, the `.git/config` SHA-256) is replaced through a synced temporary file and a rename: provisionally after `init`, then after each commit object and before the branch moves. With no record, commitStep empties `.git`'s contents and runs `init` again in its step (5); with one, the history guard reads `.git` as files before any git command. `accepted_at` is truncated to whole seconds. With `open_round` (an open review round, T076; or one reused from an earlier run, with `reused_from` and its witnesses as `outputs`, T088) the subject is `Step <step> round <round> left open in <run>`, the trailers unchanged; `open_round` without `round` is 400 InvalidRequest, as is `attempt` with `reused_from`. restoreStep removes links and entries that are not ProjectPaths only below `dir/**` folders or at an exact writable entry's path, answers 422 for one elsewhere before changing anything, and never removes a folder or touches `.git`. The FR-025 first-touch guard (`firstTouch`, `newProject`, T053e): with no record, restoreStep for attempt 1 and a commitStep with `reused_from` answer 409 ProjectExists, naming the first path found, before anything changes, when the folder holds a file or symbolic link at any depth outside `.git` or a non-empty `.git` (no link followed); a folder of empty folders and a missing or empty `.git` pass, and the call then writes a claimed record (`project`, `claimed_at`) atomically before anything else. With a claimed record, and for every other call with no record, the no-record rules above apply, so a resume repeating attempt 1 and a retry after a crash before `git init` or before the provisional record are not first touches. Known limits: only a path's last part is protected against a symbolic link swapped in after the walk (`O_NOFOLLOW`; a folder swapped for a link in between is followed), and a child that calls `setsid` leaves the process group the time limit kills; the deployment's container (constitution VIII, project mounted read-only for the check service) contains both.

Check command (`cmd/check`): settings from the environment only. Every deployment needs `CHECK_LISTEN_ADDRESS`, `CHECK_TOKEN`, `CHECK_PROJECTS_DIR` (an existing folder) and `CHECK_DEPLOYMENT` (`check-service`, `procedure-worker` or `project-worker`); the check service and a procedure worker also need `CHECK_OAPI_CODEGEN` (an executable) and `CHECK_TEMPLATE_DIR` (an existing folder); a procedure worker also needs `CHECK_PROCEDURE` and `CHECK_STEP`; the project worker needs `CHECK_HISTORY_DIR` (an existing folder for its records) and may set `CHECK_GIT` (an executable). Each deployment refuses the others' settings. `compose.yaml` runs it as the `check` service (`check-service`), with the projects folder read-only and its own token, `AP_CHECK_TOKEN`, and as `project-worker` from its own image (`Dockerfile.project`), with the projects folder writable, its records on the volume `project-worker-state` and its own token, `AP_PROJECT_TOKEN`, which the engine calls it with; the procedure step workers are the launcher's (T053d).

Fixed procedures (`procedures/`, T050): the api-feature-go pattern's steps no model runs, as functions from the step's input artifacts to its output artifacts; they compute files and write nothing into the project (writing them is the procedure step worker's job, T054c). An input is `Input{Name, SHA256, Content}` in the check contract's artifact form: `slice/<part>` holds the part's canonical JSON, any other the framed form of its files; a content without its hash is `ErrInputHashMismatch`, the only error an input can cause. An `Output` holds its files in byte order of path and the SHA-256 of their framed form. The framed form (`canonical.Framed`, `FramedHash`, `Unframe`: per file the path, LF, the length in decimal, LF, the bytes) has one owner in `canonical/`, which the engine's agent digest uses too. `ContractCheck` turns `slice/contract` and `slice/rules` into `contract` (`api/openapi.yaml`) and `examples` (`features/slice.feature`), the texts byte for byte, and refuses a wrong input set, a part that is not its JSON object and a contract `checks.ContractUnreadable` refuses (not exactly one YAML document); the lint itself is `ContractLintPasses`. `Generate` (`GenerateConfig{OapiCodegen, Template, Env, TempDir}`: the pinned binary, the catalogue's module template, environment added for `go` and oapi-codegen, and where its fresh folders are made, the call's folder in the check program, else `os.TempDir()`) turns `contract` into `generated-code`: in a fresh folder it copies the template, writes the contract, runs the template's `//go:generate oapi-codegen` line in `gen/` with the given binary, writes `gen/stub.go` (a `Stub` answering every `ServerInterface` operation 501), runs `go mod vendor` (`GOPROXY=off`, `GOFLAGS=-mod=mod`, `GOWORK=off`, `GOTOOLCHAIN=local`), requires go.mod and go.sum unchanged and `go build ./...` from `vendor/` to pass, and returns every file but the contract and the template's `vendortools/`; it does this twice and completes only when both runs give the same bytes. A rejected contract, a go.sum that disagrees with a module, a changed go.mod or go.sum and a failed build are `Completed: false`, with tool output whose host paths are removed; a tool that cannot start or an unusable template is an error. `IsProjectPath` is the check contract's ProjectPath rule. The module cache the generation needs is the one `scripts/check.sh` already fills (the engine's modules and the godog fixture's).

Contract diff (`contracts/`): `contracts.NewDiff()` is the `slices.ContractDiff`, oasdiff v1.37.0 as a Go library judging as `oasdiff breaking` in `scripts/contract-diff.sh` does (all checks, default levels); it reads JSON or YAML from memory only, refuses every external `$ref`, documents above 4 MiB and anything not OpenAPI 3, and returns an error rather than an empty result when it cannot compare. See `docs/components/oasdiff.md`.

Analyst (`analyst/`): `analyst.NewHTTP(baseURL, token, digest)` is the `slices.Analyst` that calls the analyst service (Docker Agent `serve api`, research D27) with the standard library: one titled session with `safety_policy: restricted` per call, the message from `slices.AnalystMessage`, the proposal from the last `agent_choice` and the model from `agent_info`, an error unless the stream stops with reason `normal` and no error event, the session always deleted, no retry, and at most 330 s per call.

Engine command (`cmd/engine`): `setup` reads the environment, all required and refused when missing or empty, naming the variable: `ENGINE_LISTEN_ADDRESS`; the session's tokens `ENGINE_CLIENT_TOKEN`, `ENGINE_PAGE_TOKEN`, `ENGINE_WORKER_TOKEN`; `AP_LINT_URL` and `AP_LINT_TOKEN` (contract-lint); `AP_ANALYST_URL` and `AP_ANALYST_TOKEN` (analyst); and `ENGINE_STORE_DIR`, an existing directory for the run store. `AP_CHECK_URL` and `AP_CHECK_TOKEN` (the check service). `AP_PROJECT_URL` and `AP_PROJECT_TOKEN` (the project worker), required like the others (owner, 2026-11-14), make `steps.NewHistory` the `api.Config.History`. The seven tokens must all differ, and every URL must be `http(s)` with a host. With the check service it builds the run's step worker and checker (`steps`): the agent steps' models are what their embedded definitions pin (`<provider>/<model>`); a step whose definition is not embedded (T049) has no model, so each of its attempts fails before anything is called, and no agent step's result is reused (`api.Config.Model` stays empty). It wires `slices.New` with the embedded contract's schemas, `contracts.NewDiff()`, `contracts.NewLint`, `analyst.NewHTTP` and the embedded catalogue pattern, opens the store and serves the slices kept in it (a slice record it cannot read stops it), and serves `api.NewHandler`; on SIGTERM the server stops, then running operations are cancelled, the close waits until each has ended (`api.Config.Running` counts every operation's work and each machine call driving a run, T101), and the store is closed, so nothing writes it after close returns; a run cut off this way is interrupted and resumes.

Embedded files from outside the module: Go's embed reaches only the package's folder, so `cmd/engine` names `gen/catalogue/api-feature-go/pattern.yaml`, `gen/agents/analyst.yaml` and `gen/agents/analyst/instruction.md` in `//go:embed`, and `scripts/generate.sh` copies each `gen/<path>` from `src/<path>` (gitignored; `--check` proves the copies match; `src/.dockerignore` keeps the copied `.md` in the image's build context). Run `scripts/generate.sh` after changing the pattern or the analyst's definition, and rebuild the engine image.

Agent digest: every proposal's `agent_digest` is the SHA-256 (lowercase hex) of the analyst's definition files as the analyst service mounts `src/agents` at `/agents` (`analyst.yaml`, `analyst/instruction.md`), framed so no two sets of files give the same input: for each file, in byte order of its path relative to `/agents`, the path, a line feed, its length in bytes in decimal, a line feed, then its bytes. The engine computes it from its embedded copies at start, so it names the definition the engine was built with.

API follow-ups (T038h, T040b): a request body must come with `Content-Type: application/json` (parameters allowed); a body with no Content-Type or another one is 400 InvalidRequest before its schema is checked, since the contract declares no 415. `CreateSliceRequest.description` holds at most 4000 characters (the contract's `maxLength`, counted in code points), checked with the body before any operation exists. At most 4 createSlice and answerQuestions operations work at once across one engine, as their contract descriptions state (`analystCallsAtOnce`; not in `x-limits`, whose keys the Spectral rule requires of every service): `sliceServer.withAnalyst` holds a place in a channel around the service call, so an operation beyond the limit waits, `running`, and one cancelled while it waits ends `cancelled` without calling the analyst. The place is held for the whole service call (the analyst's attempts and the checks after them), not only the analyst request, since the analyst is the service's own. Page tokens (`api/pages.go`) are opaque: the list's name and a place, signed with HMAC-SHA256 under a key made when the handler is; a token from another list, a changed or made-up one, or one from before a restart is 400 InvalidRequest. The operations list's place is an offset (that list does not change while the engine runs); listSlices' place is the number of the last slice on the page, and the next page starts at the first slice with a lower number, so slices created or deleted between pages are neither repeated nor make another skipped. An operation that ends in a refusal of the slices service keeps the refusal's failing checks in its `error.failures`.

Workers and startRun (`api/workers.go`, T053 engine side): `Config.WorkerGrants` maps each step worker's token to the slice and step it was issued for (`WorkerGrant`); such a token is a worker token besides `Tokens.Worker`, with its own rate limit. `registerWorker` with a granted token records the endpoint for that slice and step in memory (a restart forgets it), replacing an earlier one, and answers 200 with the `Worker`; a slice that does not exist, a step the pattern does not declare (`slices.Service.Steps`, read from `pattern.yaml`) and the session worker token without a grant are 404 NotFound. `startRun` refuses after `Buildable` with `WorkersNotReady` while a step of the pattern has no registered worker for the slice, then `RunActive`, then `ProjectExists` (see Run operations). `Config.GrantsDir` is a folder of grants made after start (research D31): a token that is no session token and not in `WorkerGrants` is a worker token when the folder holds a file named the lowercase hex SHA-256 of the token with exactly `{"slice","step","call_token"}`, each a non-empty string; the file is read at every such authentication, so removing it revokes the grant, and an unreadable, non-regular, larger than 4 KiB or malformed file grants nothing. `cmd/engine` reads it from `ENGINE_GRANTS_DIR` (optional; unset, no worker registers; set, it must be an existing folder). `ProjectExists` refuses a project folder only when it holds a file or symbolic link at any depth or a `.git` holding anything; a folder of empty folders (the skeleton `ap build-workers` makes) is free. `cmd/engine` does not wire the projects folder yet (T053b).

Run state machine (`machine/`, T051, T052): `machine.New(Config{Pattern, Worker, Checker, Clock, Events, Results, Model, History, Sleep})` runs one run at a time (`Start` and `Resume` refuse with `ErrRunActive` while another run has no outcome, a run waiting for the developer included) and drives it synchronously through the pattern's steps, holding its lock only to change a run and append an event, never while a worker or a check runs. Before a step runs, its reuse key (`ReuseKey(KeyParts)`: SHA-256 of length-framed pattern `<id>@<version>`, step, agent digest, `Config.Model` for agent steps, and the input hashes, which for a fix or a later review round include a hash of the findings and lines it is given; for the review step also its round, `KeyParts.Round`, which leaves every other step's key unchanged, T088) is looked up in `Config.Results`: found, the step is not run and `ResultReused` is recorded; otherwise each `StepAccepted` is stored there, so a replay (`Start` with a new run ID over the same store) reuses every accepted result, in any project. With `Config.History` (T053e; data-model.md, run rules) the machine calls `History.Restore` (restoreStep) before every attempt with `before` and `History.Commit` (commitStep) for every `StepAccepted` (with its `attempt` and `round`) and `ResultReused` (with `reused_from`, the result's run, and the stored hashes of its outputs, the review's findings aside), `accepted_at` the event's `at`, before anything for the next step and before `RunCompleted`. Each call gets what is left of the run's time budget; with less than 1 s left it is not made and the run is interrupted. A failing call (a time-out included) is retried after `Config.Sleep` waits of backoff with jitter, in (1s<<n)/2 to 1s<<n for retry n (D7), then the run is interrupted (never handed over) with the error in its reason; `Resume`, also after a restart, commits the last accepted step again first (a repeat is safe), so a crash between `StepAccepted` and its commit makes the commit once. An attempt is accepted only when every one of its checks passes, all of them run and are recorded, a check that errors counts as failed and the agent's `Done` is ignored; a result without a model, with another model than `Config.Model`, or without every declared output as a SHA-256 hash is a rejected attempt. A worker error is a rejected attempt too; when every attempt of a step fails so, or the run's context is cancelled (the platform stops), the run is `interrupted` (`RunInterrupted`) and `Resume` continues it at the step (or review round) it stopped in without running an accepted step again; check rejections on every attempt, or an attempt that takes the step (per attempt or review round) or the run (running time only) past a token, cost or time budget, hand the run over (`RunHandedOver`, the reason naming the step or budget). `ExpireDue` ends a waiting or interrupted run `expired` 14 days after it stopped, `AcceptHandOver` ends a waiting run `handed-over` and `Cancel` any run `cancelled`, at the next event when it is running. The review step (the step with the `NoBlockingFindingOpen` check) runs in rounds: a round whose only failing check is that one records its findings (each with its `witness`, `machine.Witness{File, Test}`), and when the review step has writable entries (its witnesses under `review/**`, T076) its `StepRejected` carries the round's files, which become the project's and are committed (`commitStep` with `OpenRound`, sent as `open_round: true` with that round's attempt and round and the StepRejected's `at`, before the fix's restore) so the fix and the next round start from them (data-model, "A review round"; resume rebuilds them from that event); the step before it runs again with the open blocking findings (only a finding NoBlockingFindingOpen confirmed, `machine.CheckResult.Confirmed`, mapped back by `steps` to the attempt's findings, is recorded `blocking` and given to the fix, the next round's key, the hand-over and `Run.Open`; every other one is recorded as a suggestion, and a round with no confirmed finding is rejected, not left open; the stored `findings` artifact stays the agent's answer; T096, ADR 0042), as the fix carrying the round whose findings it fixes (its events, check calls, restoreStep and commitStep and the worker's request name it, its attempts count from 1 in each round, and resume rebuilds it; T083), and the next round gets only those findings and the lines the fix changed; after `ReviewRounds` rounds the run is handed over with the open findings, once that round's commit is made. An open round's result is kept in `Config.Results` like an accepted one (`Accepted.Open`, its `Findings` in recorded order and its NoBlockingFindingOpen `Check`), and its `StepRejected` carries `open_round`, `reuse_key` and `artifacts`; a later run of the same input records the kept findings as `FindingRecorded` (no `attempt`), then a `ResultReused` with `open_round`, `check` and `detail` `review round <n> left blocking findings open`, runs no check, accepts nothing, commits the round (with `open_round` and `reused_from`, when the review has writable entries) and goes on with the fix, whose key then matches, or the hand-over at the last round. `Resume` after an open `StepRejected` or `ResultReused` makes the round's commit again and goes straight to the fix (or the hand-over), with the blocking findings recorded directly before that event; the round is not run again (research D36, ADR 0040, T088). Events marshal to the contract's `run-event.schema.json`, `seq` from 1 without gaps; `RunStarted` holds the slice's input hashes in the order of their names; each event names the run's refs unless a check names its own. When `Events` also implements `Reader`, a machine reads a run it does not hold from its record (a run whose last event is not an end, a hand-over or `RunInterrupted` is interrupted, and the machine appends one `RunInterrupted`, "the platform stopped during the run", stamped with the last event's `at`, so the downtime counts toward neither the time budget nor the expiry; T085) and resumes it, restoring the slice from `RunStarted`'s `slice`, the use so far from each attempt's `usage` (on `AttemptMade`, or on `StepRejected` for an attempt that made none) and the running time from the events' times; when it also implements `Lister`, the machine reads every listed run before its first call, so a run that exists only in the record and has not ended is active. The run store that becomes the engine's event sink (T054) must implement both `Reader` and `Lister`; without `Lister` an unended run from before a restart does not block `Start`. A fix's changed lines are recorded on its `StepAccepted` or `ResultReused` (`changed_lines`) and read back from there; a worker's negative usage counts as 0, live and when read back. With a `Results` store, `Start` refuses a pattern with an agent step while `Config.Model` is empty, before any worker runs. A cancelled run context interrupts the run, also when it comes during or after a step's last attempt; it never hands the run over. An event the sink refuses leaves the run `interrupted`. `Compare(a, b)` lists per step the artifacts, checks and decision that differ between two records; it reads a reused open round as the original open round (its check `failed: <reason>`, its decision not accepted).

Run operations (`api/runs.go`, T054): with a `Config.Store` that also implements `api.RunStore` (`*store.Store`), the engine keeps runs; one `machine.Machine` per slice, at most one active run on the platform (FR-021), its `Pattern` built from `slices.Service.Pattern()` (the pattern's one reader), its events written to the store by `runEvents` (`machine.Events`, `Reader`, `Lister`): each `store.Event` carries the whole event in `Data`, and the `RunStarted` line also the run's project, operation and `replay_of`, so a run is never recorded without them. Starts, resumes, replays and hand-overs are serialised; `startRun` refuses in the contract's order (NotFound, PatternDoesNotFit, NotApproved, WorkersNotReady, RunActive while any run of any slice has not ended, naming it and its slice, ProjectExists: the folder under `Config.Projects` holds a file or symbolic link at any depth or a non-empty `.git`, or any recorded run, ended or not, uses that project name), then `WorkersNotReady` while `Config.StepWorker` or `Config.StepChecker` is nil (T054a; `cmd/engine` wires neither yet, so every start ends there). A start that passes takes its ID from `store.NextRunID` (`run-sequence.json`, durable before use and never reissued, also after an erasure), reserves an operation ID, and answers 202 only once `RunStarted` is durable; the operation then follows the run until it ends (succeeded; cancelling it ends the run `cancelled`; an engine stop interrupts the run). `resumeRun` (NotFound, RunNotInterrupted, WorkersNotReady, RunActive for any other run not ended) records `RunResumed` before it answers with the run's operation, a new one after a restart; `replayRun` (NotFound, RunNotEnded, WorkersNotReady, RunActive as startRun, ProjectExists) starts a new run with the earlier one's inputs, refs and `replay_of`; `acceptHandOver` (NotFound, RunNotWaiting) records `HandOverAccepted` before it answers. Accepted results, and open review rounds (from the `StepRejected` or `ResultReused` with `open_round`, the `FindingRecorded` events directly before it and its NoBlockingFindingOpen result; T088), are reloaded from the record at start, the first under a key kept; with an agent step in the pattern they are reused only when `Config.Model` is set (machine rule). `getRun`, `listRuns` (newest first, 50 per page), `listRunEvents` (100 per page; a token names the events already read, and an unended run's last page keeps one), `compareRuns` (`machine.Compare`, 50 per page) and `getArtifact` (only a hash the run's record names, as `application/octet-stream`: no media type is recorded) refuse a run ID or hash that breaks the contract's rule with 400 InvalidRequest and an unknown run with 404. Reads end due runs `expired` first, and so do `startRun`, `resumeRun` and `replayRun` for every slice's runs before their RunActive check (research D38). Operation IDs live in memory and do not survive a restart: a run's recorded `operation` then names none, and resume or hand-over start a new one. `deleteSlice` is refused with 409 RunActive (after NotFound) while a run of the slice has not ended, running, interrupted or waiting for the developer (the slice edits keep this per-slice refusal); its work holds the runs' lock and checks again before it erases.

Step adapters (`steps/`, T054c): `NewWorker` and `NewChecker` give the machine's Worker and Checker, and `NewHistory` its History: restoreStep and commitStep at `Config.ProjectURL` with `Config.ProjectToken`, `time_limit_seconds` the request's time limit in whole seconds (1 to the contract's 600), a reused result's outputs loaded with `Config.Load` and checked against their hashes before anything is sent; a 200 counts only when its `project_files` equal the request's, and any other answer is an error naming the HTTP status and problem code. An agent step's attempt is one session on its registered `serve api` (`agentcall/`, shared with `analyst/`: a titled session with `safety_policy: autonomous`, since the step container under gVisor is the boundary, where the analyst's is `restricted`; the stream read until `stream_stopped`, then deleted); a model other than the step's pinned one fails it; then `readStepFiles` at the check service gives its files, whose framed form is stored as the output (the review step's outputs are its findings as JSON and, when it declares one, its witnesses, the framed files under its writable `review/**`, T076). A review finding's `witness` goes to the check service as given (left out when its file is no project path), and the fix step (the step before the review) is judged with the review among its earlier steps, so TestsUnchanged keeps the witnesses. Its usage is the last `token_usage` event of each session (the root's and any sub-session's running totals, added up; input plus output tokens, and cost), so the step and run budgets count it; its changed lines are computed from its files against the project's files it started from (a line diff), whose earlier content comes from the run's accepted outputs in the store (so it survives a restart), never taken from the agent's answer. A procedure step's attempt is `runProcedure` at its registered worker with the worker's call token (`api.WorkerGrant.CallToken`); `completed: false` fails it with the reason. A check is `runCheck` with `approved` (`slices.Service.ApprovedParts`), `before` (the project's files after the last accepted step, which the machine carries and the run record keeps beside each StepAccepted), the inputs and outputs, findings and changed lines; it passes only when the verdict passed and names the attempt's project files. A finding whose file is not a project path (or a blocking one with none) is dropped, and FindingsCarryEvidence then fails without a call. ContractLintPasses goes to contract-lint (`slices.Service.LintContract`). Any non-200 or transport error is an error.
