# src/engine

The engine: the state machine, checks, fixed procedures, run store and the engine API (contract under api/preview/).

Generated server interfaces and types: `api/gen/`, made by `scripts/generate.sh` from `api/engine.oapi-codegen.yaml`; never edited or committed.

Rate limits, both from the contract's `x-limits` and both a one-second sliding window: a request with an accepted token counts only against that token (`requests-per-second-per-token`); a request with no token, or one the engine does not accept, counts against its source address (`requests-per-second-per-address-without-token`), the host part of the connection's peer address, never a forwarding header. Such requests get 401 up to that limit and 429 with `Retry-After` beyond it. The limiter drops windows idle for a second or more, so its memory follows the addresses active in the last second, not every address ever seen.

The limits live once, in the contract's root `x-limits`; the engine refuses to start without a positive integer for each of its four keys, and the Spectral rule `ap-limits-declared` in `api/ruleset.yaml` (function `api/ruleset-functions/declaresLimits.js`) fails any service contract that lacks one.

Run store (`store/`): `store.Open(dir, ids)` takes the contract's schemas (`*slice.Schemas`) and parses every slice ID, run ID and artifact hash it is given, and every one it reads back from disk, with them; the patterns are not repeated in Go. Nothing in the engine opens the store yet; when it does (a later task), it will pass the schemas of the contract version it embeds, through `slice.LoadSchemasFS`.

Slices (`slices/`): `slices.New(Config)` takes the contract's schemas, the analyst and an oasdiff comparison (`ContractDiff`), and the catalogue pattern's `pattern.yaml` bytes for `checks.Fit` (without them every contract carries a failed `PatternFit` and cannot be approved). `Create` builds a slice from the analyst's proposal, offers an approved slice of the same description instead, and asks to narrow an empty or multi-use-case description. Every change runs the schema, `slice.Trace`, `ExampleTagged` (`slice.ExampleTags`: each scenario carries the `@R-<n>` of its `Rule:` block and an `@E-<n>` no other scenario carries) and pattern checks again, and a changed contract is compared with the last approved one, or with an empty document before any approval; a failing check is stored in the slice's `checks`, never returned as an error, and `Approve` refuses the failing part, and a part an open question concerns (`ContradictionOpen`). More than 10 questions in a proposal gives `TooManyQuestions`. A proposal is unusable when it breaks `slice-proposal.schema.json` or `slice.Trace` cannot parse its Gherkin examples or its OpenAPI contract; `Create` then asks the analyst again with that proposal and its faults (`AnalystInput.Previous`, `AnalystInput.Errors`), up to the pattern's `limits.attempts` (one attempt without a pattern or a positive limit), and after the last attempt fails with `OperationFailed` naming the faults and stores nothing. An analyst error is returned, not retried, and every other failing check is stored as before. Each part's hash is the SHA-256 of its RFC 8785 canonical JSON, written by `slices/canonical.go` for the strings, arrays and objects a part holds (no part holds a number); an approval holds only while that hash is unchanged, and a change to the part withdraws it. With `Config.Lint` (`ContractLint`: Spectral with OpenAPI's standard rules, not `api/ruleset.yaml`), a new or changed contract is linted too: each error-level finding fails `ContractLint`, warnings do not, and a lint that cannot run fails it; without a lint every contract carries a failed `ContractLint` and cannot be approved. Schema failure reasons name the part and the JSON pointer of the fault in the parts document and say what is wrong in words, never a schema's URL or a local path. `Answer` records answers to open questions (an option or a text of at most 200 characters; an answered or unknown question gives `QuestionNotOpen`), sends the description, the current proposal and all questions with their answers to the analyst under the same unusable-proposal retry, takes the revised parts and the revision's new questions (next `Q-<n>` IDs, at most 10 questions in total, else `TooManyQuestions`), checks again, withdraws the approval of each part whose hash changed and appends `answered` then `revised`; an answered question no longer blocks approval, and a refused answer changes nothing. The analyst runs without the service's lock; if the slice changed meanwhile the revision is dropped. `Delete` erases a slice; its ID is not given out again. `List` returns the slices newest first. `Reserve` gives out the next ID from the sequence `Create` also draws from, and `CreateAs` creates a slice under a reserved ID (a malformed, unreserved or used ID gives `InvalidRequest` before the analyst runs); an ID given out is never given out again, also not after a failed `CreateAs` or a `Delete`. `CheckAnswers` and `CheckApprove` refuse exactly as `Answer` (before its analyst call) and `Approve` do, and change nothing. `Buildable` gives `PatternDoesNotFit` while a pattern condition fails, then `NotApproved` while a part holds no approval at its current hash. `Slice.ArtifactCount` (`artifact_count`) is not kept by the service; it is filled from the run store's `ArtifactCount(sliceID)`, the number of distinct artifacts stored for the slice's runs. Slices are kept in memory until the engine API stores them (T038).

Contract diff (`contracts/`): `contracts.NewDiff()` is the `slices.ContractDiff`, oasdiff v1.37.0 as a Go library judging as `oasdiff breaking` in `scripts/contract-diff.sh` does (all checks, default levels); it reads JSON or YAML from memory only, refuses every external `$ref`, documents above 4 MiB and anything not OpenAPI 3, and returns an error rather than an empty result when it cannot compare. See `docs/components/oasdiff.md`.
