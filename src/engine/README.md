# src/engine

The engine: the state machine, checks, fixed procedures, run store and the engine API (contract under api/preview/).

Generated server interfaces and types: `api/gen/`, made by `scripts/generate.sh` from `api/engine.oapi-codegen.yaml`; never edited or committed.

Rate limits, both from the contract's `x-limits` and both a one-second sliding window: a request with an accepted token counts only against that token (`requests-per-second-per-token`); a request with no token, or one the engine does not accept, counts against its source address (`requests-per-second-per-address-without-token`), the host part of the connection's peer address, never a forwarding header. Such requests get 401 up to that limit and 429 with `Retry-After` beyond it. The limiter drops windows idle for a second or more, so its memory follows the addresses active in the last second, not every address ever seen.

The limits live once, in the contract's root `x-limits`; the engine refuses to start without a positive integer for each of its four keys, and the Spectral rule `ap-limits-declared` in `api/ruleset.yaml` (function `api/ruleset-functions/declaresLimits.js`) fails any service contract that lacks one.

Run store (`store/`): `store.Open(dir, ids)` takes the contract's schemas (`*slice.Schemas`) and parses every slice ID, run ID and artifact hash it is given, and every one it reads back from disk, with them; the patterns are not repeated in Go. The engine command opens it in `ENGINE_STORE_DIR` with the schemas of the contract version it serves (`api.ContractFiles()` through `slice.LoadSchemasFS`); the API reads `artifact_count` from it and erases a deleted slice's data in it. It also keeps the slices (T038b), behind `slices.Records`: `slices/<id>/slice.json` holds each slice's record and `slice-sequence.json`, at the store's root, the last slice ID given out, both readable JSON replaced atomically (temporary file, fsync, rename, fsync of the folder) and written before the change is reported; `Open` removes leftover temporary files and `EraseSlice` removes the record with the slice's folder. The slices package owns the record's format: the slice, its contract baseline (the last approved contract) and its latest compatibility and lint results, so a restart serves the same parts, hashes, checks, questions, answers, approvals, history and state without calling the lint service or the analyst. On load each record is checked: its layout version, the slice ID against the contract's rule, the state, each approval's part and hash against the contract's rule, and that the stored part hashes are those of the stored parts. The ID sequence keeps the IDs of deleted and reserved slices from being given out again; if storing it fails in `Reserve`, no slice is stored until a later write succeeds.

Slices (`slices/`): `slices.New(Config)` takes the contract's schemas, the analyst and an oasdiff comparison (`ContractDiff`), and the catalogue pattern's `pattern.yaml` bytes for `checks.Fit` (without them every contract carries a failed `PatternFit` and cannot be approved). `Create` builds a slice from the analyst's proposal, offers an approved slice of the same description instead, and asks to narrow an empty or multi-use-case description. Every change runs the schema, `slice.Trace`, `ExampleTagged` (`slice.ExampleTags`: each scenario carries the `@R-<n>` of its `Rule:` block and an `@E-<n>` no other scenario carries) and pattern checks again, and a changed contract is compared with the last approved one, or with an empty document before any approval; a failing check is stored in the slice's `checks`, never returned as an error, and `Approve` refuses the failing part, and a part an open question concerns (`ContradictionOpen`). More than 10 questions in a proposal gives `TooManyQuestions`. A proposal is unusable when it breaks `slice-proposal.schema.json` or `slice.Trace` cannot parse its Gherkin examples or its OpenAPI contract; `Create` then asks the analyst again with that proposal and its faults (`AnalystInput.Previous`, `AnalystInput.Errors`), up to the pattern's `limits.attempts` (one attempt without a pattern or a positive limit), and after the last attempt fails with `OperationFailed` naming the faults and stores nothing. An analyst error is returned, not retried, and every other failing check is stored as before. Each part's hash is the SHA-256 of its RFC 8785 canonical JSON, written by `slices/canonical.go` for the strings, arrays and objects a part holds (no part holds a number); an approval holds only while that hash is unchanged, and a change to the part withdraws it. After any change (`Replace*` or `Answer`), every other part that now fails a check, such as rules naming a removed goal or a contract whose `x-rules` names a removed rule, loses its approval too, recorded as a `withdrawn` history entry whose `refs` are those parts; a slice is never `approved`, offered for reuse or buildable while a check fails. With `Config.Lint` (`ContractLint`: Spectral with OpenAPI's standard rules, not `api/ruleset.yaml`), a new or changed contract is linted too: each error-level finding fails `ContractLint`, warnings do not, and a lint that cannot run fails it; without a lint every contract carries a failed `ContractLint` and cannot be approved. Schema failure reasons name the part and the JSON pointer of the fault in the parts document and say what is wrong in words, never a schema's URL or a local path. `Answer` records answers to open questions (an option or a text of at most 200 characters; an answered or unknown question gives `QuestionNotOpen`), sends the description, the current proposal and all questions with their answers to the analyst under the same unusable-proposal retry, takes the revised parts and the revision's new questions (next `Q-<n>` IDs, at most 10 questions in total, else `TooManyQuestions`), checks again, withdraws the approval of each part whose hash changed and appends `answered` then `revised`; an answered question no longer blocks approval, and a refused answer changes nothing. The analyst runs without the service's lock; if the slice changed meanwhile the revision is dropped. `Delete` erases a slice; its ID is not given out again. `List` returns the slices newest first. `Reserve` gives out the next ID from the sequence `Create` also draws from, and `CreateAs` creates a slice under a reserved ID (a malformed, unreserved or used ID gives `InvalidRequest` before the analyst runs); an ID given out is never given out again, also not after a failed `CreateAs` or a `Delete`. `CheckAnswers` and `CheckApprove` refuse exactly as `Answer` (before its analyst call) and `Approve` do, and change nothing. `Buildable` gives `PatternDoesNotFit` while a pattern condition fails, then `NotApproved` while a part holds no approval at its current hash or any check fails. `Slice.ArtifactCount` (`artifact_count`) is not kept by the service; it is filled from the run store's `ArtifactCount(sliceID)`, the number of distinct artifacts stored for the slice's runs. With `Config.Records` (the run store in the engine), slices are durable: `New` loads every stored slice and the ID sequence and fails, naming the slice, on a record it cannot read or check (fail closed); every change is written before it is reported. Without it slices live in memory only.

Contract diff (`contracts/`): `contracts.NewDiff()` is the `slices.ContractDiff`, oasdiff v1.37.0 as a Go library judging as `oasdiff breaking` in `scripts/contract-diff.sh` does (all checks, default levels); it reads JSON or YAML from memory only, refuses every external `$ref`, documents above 4 MiB and anything not OpenAPI 3, and returns an error rather than an empty result when it cannot compare. See `docs/components/oasdiff.md`.

Analyst (`analyst/`): `analyst.NewHTTP(baseURL, token, digest)` is the `slices.Analyst` that calls the analyst service (Docker Agent `serve api`, research D27) with the standard library: one titled session with `safety_policy: restricted` per call, the message from `slices.AnalystMessage`, the proposal from the last `agent_choice` and the model from `agent_info`, an error unless the stream stops with reason `normal` and no error event, the session always deleted, no retry, and at most 330 s per call.

Engine command (`cmd/engine`): `setup` reads the environment, all required and refused when missing or empty, naming the variable: `ENGINE_LISTEN_ADDRESS`; the session's tokens `ENGINE_CLIENT_TOKEN`, `ENGINE_PAGE_TOKEN`, `ENGINE_WORKER_TOKEN`; `AP_LINT_URL` and `AP_LINT_TOKEN` (contract-lint); `AP_ANALYST_URL` and `AP_ANALYST_TOKEN` (analyst); and `ENGINE_STORE_DIR`, an existing directory for the run store. The five tokens must all differ, and both URLs must be `http(s)` with a host. It wires `slices.New` with the embedded contract's schemas, `contracts.NewDiff()`, `contracts.NewLint`, `analyst.NewHTTP` and the embedded catalogue pattern, opens the store and serves the slices kept in it (a slice record it cannot read stops it), and serves `api.NewHandler`; on SIGTERM the server stops, then running operations are cancelled and the store is closed.

Embedded files from outside the module: Go's embed reaches only the package's folder, so `cmd/engine` names `gen/catalogue/api-feature-go/pattern.yaml`, `gen/agents/analyst.yaml` and `gen/agents/analyst/instruction.md` in `//go:embed`, and `scripts/generate.sh` copies each `gen/<path>` from `src/<path>` (gitignored; `--check` proves the copies match; `src/.dockerignore` keeps the copied `.md` in the image's build context). Run `scripts/generate.sh` after changing the pattern or the analyst's definition, and rebuild the engine image.

Agent digest: every proposal's `agent_digest` is the SHA-256 (lowercase hex) of the analyst's definition files as the analyst service mounts `src/agents` at `/agents` (`analyst.yaml`, `analyst/instruction.md`), framed so no two sets of files give the same input: for each file, in byte order of its path relative to `/agents`, the path, a line feed, its length in bytes in decimal, a line feed, then its bytes. The engine computes it from its embedded copies at start, so it names the definition the engine was built with.

API follow-ups (T038h, T040b): a request body must come with `Content-Type: application/json` (parameters allowed); a body with no Content-Type or another one is 400 InvalidRequest before its schema is checked, since the contract declares no 415. `CreateSliceRequest.description` holds at most 4000 characters (the contract's `maxLength`, counted in code points), checked with the body before any operation exists. At most 4 createSlice and answerQuestions operations work at once across one engine, as their contract descriptions state (`analystCallsAtOnce`; not in `x-limits`, whose keys the Spectral rule requires of every service): `sliceServer.withAnalyst` holds a place in a channel around the service call, so an operation beyond the limit waits, `running`, and one cancelled while it waits ends `cancelled` without calling the analyst. The place is held for the whole service call (the analyst's attempts and the checks after them), not only the analyst request, since the analyst is the service's own. Page tokens (`api/pages.go`) are opaque: the list's name and a place, signed with HMAC-SHA256 under a key made when the handler is; a token from another list, a changed or made-up one, or one from before a restart is 400 InvalidRequest. The operations list's place is an offset (that list does not change while the engine runs); listSlices' place is the number of the last slice on the page, and the next page starts at the first slice with a lower number, so slices created or deleted between pages are neither repeated nor make another skipped. An operation that ends in a refusal of the slices service keeps the refusal's failing checks in its `error.failures`.
